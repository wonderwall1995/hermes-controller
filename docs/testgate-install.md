# testgate의 install.sh가 바꾸는 것

testgate 저장소의 `scripts/install.sh`가 **정확히 무엇을 바꾸고 무엇을 바꾸지 않는지** 적은 문서이다. 라이브 반영 2단계([setup.md](setup.md))를 하기 전에 읽는 용도이다. 경로의 `<홈>`은 Hermes 홈 폴더(`HERMES_HOME`, 기본 `~/.hermes`)이고 `<testgate 저장소>`는 testgate를 받아 둔 폴더이다.

이 스크립트는 testgate의 것이다. 이 저장소(controller)에는 설치하는 파일이 없다. 아래 내용은 스크립트의 소스를 읽고, 설치본과 원본을 비교해서 정리했다.

## 한 줄 요약

- `<홈>` 안의 **파일 몇 개를 새로 쓰거나 덮어쓴다.** 지우는 것은 분석기 패키지 폴더 하나(`<홈>/testgate/lib/testgate`)뿐이고, 곧바로 다시 만든다.
- Hermes의 소스, 설정, 웹훅 라우트, 비밀 값, testgate의 설정 파일과 보고서는 **건드리지 않는다.**
- 인터넷에 접속하지 않고, 프로그램을 실행하거나 재시작하지 않는다. 파일을 복사해 쓰는 것이 전부이다.

## 쓰는 파일

| 위치 | 내용 | 원본 |
|---|---|---|
| `<홈>/scripts/testgate_qa_filter.py` | 웹훅 라우트가 실행하는 필터 | `<testgate 저장소>/scripts/qa_filter.py` |
| `<홈>/testgate/lib/testgate/*.py` | 분석기 패키지(파이썬 파일 전부) | `<testgate 저장소>/testgate/` |
| `<홈>/testgate/testgate-run` | 필터가 백그라운드로 시작하는 래퍼(셸 스크립트) | 스크립트가 직접 생성 |
| `<홈>/testgate/README.md` | Hermes가 읽는 안내 문서 | `<testgate 저장소>/docs/hermes-guide.md` |
| `<홈>/testgate/config.path` | 설정 파일 위치를 적은 한 줄짜리 안내 파일 | 스크립트가 직접 생성 |

- 필요한 폴더(`<홈>/scripts`, `<홈>/testgate`)가 없으면 만든다.
- 쓰는 파일의 맨 아래에 "현재 Repo로 생성한 파일입니다. 직접 고치지 않고 `scripts/install.sh`로 다시 설치합니다"라는 표시를 붙인다. 여러 프로젝트가 `<홈>`을 같이 쓰기 때문에 출처를 구분하려는 것이다.
- 파이썬 파일의 권한은 원본을 따른다(지금은 664). 래퍼는 755이다. 안내 문서와 `config.path`는 사용자의 기본 `umask`를 따른다. 설치되는 파일에 비밀 값은 없다.
- `config.path`에는 **testgate 저장소의 절대 경로**가 들어간다. 이 파일은 `<홈>`에만 있고 Git에는 올라가지 않는다.
- 래퍼에는 `HERMES_HOME`과 `PYTHONPATH`를 정하는 줄과, 출력을 `<홈>/logs/testgate.log`로 보내는 줄이 들어 있다. 로그는 소유자만 읽을 수 있게(umask 077) 쓰고, 1MB를 넘으면 한 세대(`.1`)만 남긴다.

## 지우는 파일

딱 하나이다: **`<홈>/testgate/lib/testgate` 폴더**(`rm -rf`). 옛 버전에만 있던 파이썬 파일이 남지 않게 하려는 것이다. 바로 뒤에 새 파일로 다시 채운다.

주의: 지우고 다시 쓰는 사이(순식간)에 분석이 시작되면 그 분석은 실패할 수 있다. 설치는 `/qa` 요청이 없을 때 한다.

## 건드리지 않는 것

| 대상 | 이유 |
|---|---|
| Hermes 소스 폴더(`hermes-agent`) | 스크립트가 거기에 쓰지 않는다. 설치 위치는 `<홈>` 아래뿐이다. |
| `<홈>/config.yaml`, `<홈>/.env` | 설정과 비밀 값은 읽지도 쓰지도 않는다. |
| 웹훅 라우트와 구독 | 라우트는 그대로 필터 파일을 가리킨다. 필터의 *내용*만 바뀐다. |
| `<testgate 저장소>/testgate.json` | 허용 계정과 분석 설정. 스크립트는 읽을 수 있는지만 확인하고 경고를 낸다. |
| `<홈>/testgate/reports`, `requests`, `threads` | 보고서와 요청과 대화 기록. 설치는 이 폴더들을 만들지도 지우지도 않는다. |
| `<홈>/logs/` | 래퍼가 쓰는 로그. 설치는 건드리지 않는다. |

## 끝에 나오는 경고

- `testgate.json`이 없거나 읽을 수 없으면 경고한다. 설정 파일이 없으면 필터가 모든 요청을 버린다.
- 옛 위치 `<홈>/testgate.json`이 남아 있으면 경고한다(이제 쓰지 않는다). 경고만 하고 지우지 않는다.

## 알아 둘 점

- **저장소의 작업 폴더 상태 그대로 복사한다.** 커밋하지 않은 수정이 있어도 그 내용이 설치된다. 설치 전에 `git status`로 깨끗한지 본다.
- **손으로 고친 설치본은 덮어쓴다.** 설치본은 직접 고치지 않는 파일이다.
- 같은 명령을 다시 실행해도 결과가 같다(여러 번 실행해도 안전하다).
- 설치 도중 오류가 나면(`set -e`) 그 자리에서 멈춘다. 되돌리는 기능은 없다. 파일이 일부만 바뀐 채로 남을 수 있으니 다시 실행하면 된다.

## 설치 없이 확인하기

```
scripts/install.sh --check      # 또는 pnpm filter:check
```

설치하지 않는다. 원본으로 임시 폴더에 설치본을 만들어 `<홈>`의 파일과 비교하고, 다른 파일을 알려 준다. 같으면 `원본과 설치본이 같다`를 출력한다. 다르면 종료 코드 1이다. 읽기만 하므로 언제 실행해도 안전하다.

## 이번 설치에서 달라지는 것

설치하기 전에 `--check`와 파일별 비교를 한 결과이다(원본은 testgate의 `feat/context-file` 변경이 들어간 main).

| 파일 | 상태 | 바뀌는 내용 |
|---|---|---|
| `scripts/testgate_qa_filter.py` | 바뀜 | 설정의 `start_command`를 읽어, 있으면 그 명령으로 분석을 시작한다. 없으면 지금처럼 래퍼를 직접 시작한다. |
| `testgate/lib/testgate/contextfile.py` | 새 파일 | 요청 파일 옆의 해설 파일(`<배달ID>.context.json`)을 읽고 검사한다. |
| `testgate/lib/testgate/knowledge.py`, `analyze.py`, `run.py` | 바뀜 | 해설 파일이 있으면 분석에 붙이고, 보고서 "비고"에 한 줄을 남긴다. |
| `testgate/README.md` | 바뀜 | 안내 문서에 시작 명령과 해설 파일 설명이 추가된다. |
| 나머지 파이썬 파일 12개, `testgate-run`, `config.path` | 같음 | 내용은 그대로 다시 쓴다. |

**설정에 `start_command`를 적기 전에는 동작이 바뀌지 않는다.** 필터는 예전처럼 래퍼를 바로 시작하고, 해설 파일이 없으면 분석기는 예전처럼 동작한다. 이것은 testgate의 시험(284개)으로 확인했다. 실제 환경에서 `/qa`로 확인하지는 않았다.

## 되돌리기

설치 전에 `<홈>/scripts/testgate_qa_filter.py`와 `<홈>/testgate/`(reports, requests, threads 제외)를 다른 폴더에 복사해 두면 그대로 되돌릴 수 있다. 복사해 두지 않았다면, testgate 저장소에서 이전 커밋을 받아(`git checkout <이전 커밋>`) `scripts/install.sh`를 다시 실행한다. 옛 코드가 다시 설치된다.

## 확인하지 못한 것

- Hermes 업데이트(`hermes update`)가 `<홈>/scripts/`와 `<홈>/testgate/`를 건드리는지. 읽어 본 코드에는 관련된 부분이 없었다. 업데이트 뒤에는 `--check`를 한 번 돌려 본다([setup.md](setup.md) 참고).
- 실제 환경에서 설치 직후 첫 `/qa`가 정상 동작하는지. 이것은 라이브 반영 4단계에서 확인한다.
