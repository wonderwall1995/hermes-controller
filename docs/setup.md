# 실제 환경에 반영하는 순서

**상태: 아직 반영하지 않았다.** 이 문서는 순서와 되돌리는 방법을 적은 것이다. 각 단계는 사용자가 확인한 뒤에 한다. 경로는 모두 예시이다.

## 준비물

- 이 저장소(hermes-controller)
- ced-taker 저장소와 그 로컬 설정(볼트 위치)
- testgate 저장소의 새 브랜치(시작 명령 설정과 참고 자료 파일 읽기). **아직 병합되지 않았다.**
- github-app이 돌고 있고, 서명 키가 Hermes의 환경 변수로 들어가 있다(testgate가 지금 쓰는 것과 같다).

## 단계

각 단계 뒤에 멈추고 확인한다.

1. **controller 설정 파일 만들기** (`local/config.json`, Git 제외). 키 값은 쓰지 않고 환경 변수의 **이름**만 쓴다.
   ```json
   {
     "ced_taker_command": ["<ced-taker 저장소>/bin/ced-taker", "provide"],
     "github_app_url": "http://127.0.0.1:3200",
     "github_app_secret_env": "TESTGATE_GITHUB_APP_SECRET"
   }
   ```
   - `wrapper_command`를 쓰지 않으면 표준 설치 위치의 testgate 래퍼를 쓴다.
   - `ced_taker_command`가 없으면 해설을 만들지 않고, 보고서 비고에 `not_configured`가 남는다.
2. **testgate 변경을 병합하고 설치한다.** 이 일은 testgate의 몫이다. testgate 저장소에서 `scripts/install.sh`를 실행한다.
3. **testgate 설정에 시작 명령을 적는다** (`testgate.json` 최상위, Git 제외).
   ```json
   "start_command": ["<이 저장소>/bin/hermes-controller"]
   ```
   첫 인자는 절대 경로여야 한다. 배달 ID는 필터가 마지막 인자로 붙인다. 설정 파일을 고친 직후, 필터가 설정을 읽을 수 있는지 한 번 확인한다(오타가 있으면 모든 코멘트 이벤트에서 필터가 실패한다).
4. **실제 `/qa` 코멘트로 시험한다.** 분석 보고서의 "비고"에 `참고 문서 N건이 첨부됨: …` 한 줄이 있는지 본다. 이때 GitHub에 Bot 코멘트가 실제로 달린다.
5. **로그를 본다.** `<홈>/logs/controller.log`에 배달 ID와 단계, 사유 코드만 남아 있어야 한다.

## 되돌리기

`testgate.json`에서 `start_command` 항목을 지운다. 필터가 다시 래퍼를 직접 시작한다. controller와 ced-taker는 그대로 두어도 영향이 없다. testgate 필터는 이벤트마다 새로 실행되어 설정 파일을 그때마다 읽는다(소스에서 확인했다). 그래서 재시작은 필요 없다고 본다. 실제 환경에서 시험하지는 않았다.

## 알려진 위험

- **래퍼 시작 전의 강제 종료**: controller가 래퍼를 시작하기 전에 강제로 종료되면(예: 시스템이 프로세스를 죽임) 분석도 실패 코멘트도 없이 요청만 남는다. 오류와 중단 신호는 막지만 강제 종료까지는 막지 못한다. 보고서가 오래 없는 요청을 알아채는 감시자는 아직 없다.
- **지연**: 해설을 만드는 데 최대 약 35초가 더 든다(PR 조회 15초, 설명 20초의 시간 제한). 보통은 몇 초이지만 **실제로 측정하지 않았다.** 분석 자체는 25~55초 걸린다.
- **시작 명령 오타**: `start_command`의 형식이 틀리면 필터가 요청을 저장하기 전에 실패한다. 기본값으로 조용히 돌아가지 않는다. 분석 전체가 멈출 수 있으니 적은 직후 확인한다.
- **PR 정보를 두 번 조회한다**: controller와 testgate가 각자 가져온다. 서로 독립을 유지하려는 선택이다.

## Hermes 업데이트 뒤에 확인할 것

설치된 testgate 사본이 원본과 같은지 한 줄로 확인한다. testgate 저장소에서:

```
pnpm filter:check
```

`원본과 설치본이 같다`가 나오면 된다. 달라졌으면 `pnpm filter:install`로 다시 복사한다. 이 저장소(controller)는 설치하는 파일이 없으므로 이 확인이 필요 없다.

- 설치되는 곳은 Hermes 소스 폴더 **밖**의 `<홈>/scripts/`와 `<홈>/testgate/`이다.
- Hermes 업데이트가 이 두 곳을 건드리는지는 **확인하지 못했다.** 읽어 본 업데이트 코드(진행 표시, 잠금)에는 관련 코드가 없었다. `hermes update` 전체의 동작은 확인하지 못했다.

## 확인하지 못한 것

- Hermes가 필터를 실행할 때 환경 변수(서명 키)가 필터의 환경에 들어 있는지. 필터가 띄운 프로세스가 필터의 환경을 물려받는 것은 시험으로 확인했지만, Hermes가 `.env`의 값을 필터에 넘기는지는 Hermes 쪽이라 확인하지 못했다. 안 들어 있으면 PR 조회가 `github_no_secret`으로 실패하고 해설 없이 분석한다(분석은 일어난다).
- 실제 `/qa` 코멘트로 하는 전체 흐름. 지금까지의 확인은 가짜 래퍼와 가짜 서버로 한 오프라인 리허설이다.
- 해설을 만드는 데 걸리는 실제 시간.
