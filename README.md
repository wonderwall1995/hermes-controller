# hermes-controller

PR 분석 요청이 들어왔을 때 **"컬럼 설명을 먼저 붙이고, 그다음 분석한다"** 는 순서를 지키게 하는 연결 스크립트이다.

> 초기 단계이다. 구현과 시험은 끝났고, **실제 환경에는 아직 연결하지 않았다.** 지금 되는 것과 아닌 것은 [지금 상태](#지금-상태)에 적었다.

## 왜 만드는가

PR의 diff에는 `balance`, `status` 같은 이름이 나온다. 이름만으로는 뜻을 알 수 없고, AI가 추측하면 곡해한다. 그래서 DB 컬럼의 뜻을 사람이 확인해 적어 둔 문서(CED)를 ced-taker가 관리한다. 분석을 맡은 testgate는 그 문서가 무엇이고 누가 만들었는지 모른 채, 분석 직전에 놓인 참고 자료만 읽는다.

이 둘이 서로를 모르게 하려면, **누군가 순서를 정해 줘야 한다.** 그 일이 이 프로젝트의 전부이다.

## 무엇이 있는가

```
github-app (PR 정보 공급)
      |
      v
hermes-controller  ... 순서를 정한다
      |  1) PR 정보를 한 번 가져온다
      |  2) ced-taker에게 컬럼 설명을 만들게 한다
      |  3) 결과를 참고 자료 파일로 둔다
      |  4) testgate의 분석을 시작한다
      v
testgate (분석)
```

## 어떻게 할 것인가

- **어떤 오류가 나도 분석은 일어난다.** 설명을 못 만들어도, PR 정보를 못 가져와도, 설정이 틀려도 마지막에 분석을 시작한다. 이 약속을 구조로 지킨다(오류를 잡는 `try` 바깥의 `finally`에서 분석을 시작).
- **못 만든 이유는 보고서에 남는다.** 설명 없이 분석했다면 사유 코드 한 줄이 분석 보고서에 남아, 조용히 빠지지 않는다.
- **서로의 코드를 가져오지 않는다.** 명령, 파일, API의 약속으로만 부른다. 다른 프로젝트가 없어도 이 프로젝트의 시험은 가짜 명령과 가짜 서버로 통과한다.
- **내용은 기록에 남기지 않는다.** 로그에는 배달 ID, 단계, 사유 코드, 오류의 종류와 위치만 남는다. 요청 내용, PR의 제목과 diff, 설명 본문, 서명 키, 오류 메시지는 남기지 않는다.
- **서명 키는 파일에 쓰지 않는다.** 환경 변수의 이름만 설정에 적고, 값은 환경 변수에서만 읽는다.
- **자유 대화와 안내만 하는 요청에서는 설명을 만들지 않는다.** 불필요한 조회와 지연을 피한다.

## 하지 않는 것

- 컬럼 설명을 만들거나 고치지 않는다. ced-taker의 몫이다.
- PR을 분석하지 않는다. testgate의 몫이다.
- QA가 쓴 서술 원문을 읽어서 보관하지 않는다.
- 여러 파이프라인을 다루지 않는다. 지금은 이 한 가지이다.

## 지금 상태

**되는 것** (가짜 명령과 가짜 서버로 시험했고, 세 프로젝트를 한 줄로 이어 오프라인으로 확인했다)
- 요청 파일 읽기, 서명된 PR 조회, 설명 만들기, 참고 자료 파일 쓰기, 분석 시작
- 모든 실패 경로에서 분석 시작
- 설정이 없거나 틀려도 분석 시작

**아직 안 되는 것 / 하지 않은 것**
- 실제 환경에 연결하지 않았다. 설치, 설정, 실제 PR로 하는 시험은 [절차 문서](docs/setup.md)에 단계별로 적었고 사용자 확인 뒤에 한다.
- 참고 자료를 받는 쪽(testgate)의 변경은 아직 병합되지 않았다.
- 분석을 시작하기 전에 이 프로그램이 강제로 종료되면 요청이 조용히 사라질 수 있다. 줄이는 방법은 할 일 목록에 있다.

이 저장소에는 개인 정보, 접속 정보, 개인 경로, 서명 키를 넣지 않는다. 시험 자료는 모두 가짜이다. 위치와 같은 환경 설정은 환경 변수나 Git에서 제외된 로컬 설정 파일에서 읽는다.
